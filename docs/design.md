# 技术设计

## 产品流程

### 定数跳

用户设置每组次数、组数和休息时长。训练先等待人物全身入镜并完成约 0.7 秒的校准（不要求站立不动），之后进入 ARMED 等待第一跳；第一跳触发该组开始计时并计入。达到目标次数后自动进入休息，休息结束后再次进入 ARMED 等待下一组的第一跳。最后一组完成后保存训练摘要。

### 定时跳

用户设置每组有效运动时间、组数和休息时长。只有 ACTIVE 阶段消耗训练时间，暂停、等待第一跳（ARMED）和休息均不计入有效运动时间。

### 自由跳绳

从第一跳开始持续计数，直到用户主动结束。主动结束在自由模式下视为正常完成。

## 数据流

```text
CameraX RGBA 帧
  -> 旋转到显示方向
  -> MediaPipe LIVE_STREAM 姿态识别
  -> 33 个归一化人体关键点
  -> 关键点质量门控
  -> JumpDetector
  -> WorkoutEngine
  -> Compose UI + 本地训练摘要
```

CameraX 使用 `STRATEGY_KEEP_ONLY_LATEST`，推理速度落后于摄像头时主动丢弃旧帧，避免延迟持续累积。

## JumpDetector

关键输入为左右肩、髋、膝和脚踝。检测步骤：

1. 收集 20 个合格帧（约 0.7 秒），取窗口内髋部和左右脚踝的最低点作为地面基线，躯干长度取中位数；不要求站立不动。校准完成后把这 20 帧重新送入状态机，补记校准期间完成的跳跃。
2. 使用肩髋距离作为身体尺度，将垂直位移归一化。
3. 脚踝位移权重为 0.72，髋部位移权重为 0.28。
4. 对合成位移做指数平滑。
5. 用上升速度、腾空高度、落地高度和持续时间驱动有限状态机。
6. 只有左右脚同步上升时才进入起跳状态，一个完整落地周期计数一次，并执行 180ms 防重复计数。
7. 人体尺度突变时视为走近或远离镜头并重新校准，关键点丢失超过 900ms 后也会重新校准。

检测器不依赖 Android 或 MediaPipe 类型，可用合成轨迹执行 JVM 单元测试。

## WorkoutEngine

训练状态包括：

```text
COUNTDOWN -> ACTIVE -> REST -> COUNTDOWN -> ... -> COMPLETE
                  \-> PAUSED -> 原状态
```

引擎使用单调时钟计算时间，避免系统时间校准影响训练过程。壁钟时间只用于训练记录的日期显示。

## 隐私

- 模型随 APK 分发并在设备端运行。
- 无网络权限。
- 不写入摄像头视频或关键点轨迹。
- 只保存模式、日期、次数、组数、有效运动时长和完成状态。

## 验证计划

- JVM 测试：训练阶段流转、暂停计时、合成跳跃、轻微晃动不误计。
- Android 真机：权限、前后摄切换、生命周期、前台/后台恢复、提示音和振动。
- 视频回归：逐段人工标注真实次数，与设备端结果比较漏计和误计。
- 目标场景：正常光线、低光、深浅衣服、2–4 米距离、120–180 次/分钟。
